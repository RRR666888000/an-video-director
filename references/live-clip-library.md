# 大量直播切片：入库、归并、组片与复盘

收到多场直播或大量切片、需要持续复用时加载本页；单条修改无需建库。标签见 [词表](clip-taxonomy.json)，表达判断见 [内容判断](content-core.md)，执行与验收见 [制作](production.md)，登记与裁切入口见 [工具与格式](clip-library-format.md)。无需课程原文。

## 1. 入库保留来源

- 原片只读保留，衍生文件另存。为每个源文件建立稳定 `source_id`、内容哈希、原文件名、位置、时长、录制日期（未知留空）。改名不换 ID；内容变化另立 ID 并关联旧版。
- 以完整意思切分：保留问题与回答、条件与结论、指代对象、完整动作及结果；按语义转折或新话题拆，不固定秒数。时间用原片 `start_s/end_s`，采用左闭右开区间，另可显示时分秒；不得以裁切后时间替代源时间。
- 每段有稳定 `clip_id`、源 ID、时间窗、原意/转写、可见动作、限制及复核记录。切点修订留版本；已有独立切片追不到长原片时，就以该文件为源并注明追溯边界。

## 2. 多标签标注与覆盖

| 字段 | 记录内容 |
|---|---|
| `product_identity` | 稳定商品 ID 列表，区分款式/规格/版本；未知留空并说明依据缺口 |
| `topic` | 本段具体谈什么，如“快取钥匙”；可多选，不写空泛“卖点” |
| `content_roles` | 候选作用：可吸引、识别人群、品类、特点、体验、证据、顾虑、选择、人物、行动、补充画面、直播事务 |
| `evidence_types` | 画面细节、连续动作、本人感受、外部记录等；另记证明什么及不能证明什么 |
| `emotional_state` | 已见/已表达的说话者状态；期望观众反应放组片假设，不能当已发生效果 |
| `semantic_complete/context_dependency` | 意思是否完整、依赖哪句/哪件物/哪个直播状态 |
| `timeliness/use_status/review_status` | 时效、当前用途适配、实际复核进度分别记录；具体枚举见词表 |

`content_roles` 是候选作用；同一段可多标签，在计划里用 `actual_role` 确定本次作用。能吸引人不等于必须放开头。

每文件维护时间覆盖：未处理、初标、已复核的区间与去重秒数/总时长；区间不得重复计数。另分开记录转写已具备范围、文本已核验范围和实际视听复核区间；文件或转写已提供不等于助手已读过。`proposed` 为初标，`transcript_checked` 只确认文本，`av_checked` 才表示该时间窗已看画面并听原声，记录复核者/方式、时间、范围、发现。

报告如“60 分钟：未处理 35、初标 20、已复核 5；另完成全量转写”。转写、抽帧、自动分类或抽查均不能称全片看完；只看画面未听声音也不能记 `av_checked`。

大批量按源 ID/哈希去重后增量登记，逐批选窗、初标、复核，保存进度和失败项；新文件不重跑旧结果。用户已要求直接剪时，继续可确定部分，只集中列出少量会改变事实或用途的缺项，不强制逐条确认。

## 3. 相似段归并

先按商品、主题、原意找 `duplicate_group_id`，再核对动作与上下文；相似措辞不一定同义，不同商品不因同一句卖点合并成同一证据。各段保留来源、差异及代表段理由。

代表段优先满足本次目标、语义完整、依据准确、声画清楚、时效有效；不同目的可选不同代表。重复段保留备用，不删源片。有争议、旧活动、笑场分别判断：广告可暂列 `not_for_current_goal`；自然人物内容可能可用，仍须完整上下文。旧价与旧福利不能剪成当前承诺。

## 4. 组片约束与批量执行

每计划记录 `purpose/hypothesis/target_product_id`、独立方向 ID、变体 ID、目标入口，以及 `segments[{clip_id,actual_role,relation}]`。品类内容可不指定单款；涉及的多款必须说明比较关系。

- 先让每段推进本条承诺，不强套三段式；位置可重排，条件、因果、问答和动作前后关系不能被拼反。
- 用 A 款近景接 B 款效果口播会误导；跨款比较须标明身份及比较条件。无特定商品的气氛画面也不得冒充效果证明。
- 证据只能支持原来能证明的内容；本人感觉不替代检测，连续演示不扩大为长期效果。标明哪段支持哪项主张。
- CTA 必须与前文商品、问题、有效活动及实际目的地匹配。身份不明、前提缺失、时效未核实的依赖项先解决，其余继续。

先做代表样片，覆盖典型来源、弱人声、长句及拼接；通过视听检查后批量执行。先核实当前有无可用登记/转写/裁切/拼接工具；有工具就按授权处理，缺工具则交付能完成的记录与计划，明确未生成媒体。抽样通过不代表所有成片合格；导出后逐条检查实际使用时间窗、切口、字幕和声音，记录核验范围。

## 5. 合成小样例（非真实素材）

假设 `src_demo` 中商品均为 `bag_a_v1`，以下窗口已保留完整动作与话语；时码仅示范。

| ID / 原片秒数 | 内容 | 候选作用 |
|---|---|---|
| c01 / 10–19 | “赶车时钥匙放外格”，连续取出钥匙 | hook、audience、experience、evidence |
| c02 / 25–31 | 展示外侧两格、内侧一格 | feature、evidence、broll |
| c03 / 40–50 | “我以前乱放，现在换包也固定钥匙位置”，自然笑声 | persona、experience |
| c04 / 55–60 | “进直播间看这款装取演示” | cta |

方向 A“快取方便”：c01 作体验引入 → c02 作结构依据 → c04 作承接；先核实直播有该款演示。
方向 B“认识一个人的收纳习惯”：c03 作人物叙述 → c01 作行动细节，以自然动作收尾，无须销售结尾。c01 在此不是开头。

这是 **2 个独立方向**；A 换标题是变体，c02 单独导出是模块，不能相加称 4 个创意。方向是否成立还须实际素材与目标验证。

## 6. 交付与复盘

交付源片索引、已选片段/计划、可看成片及未完成项，分别报独立方向、变体、模块数量与每文件覆盖。记录成片版本、片段及作用、平台素材 ID、目的和假设。按 [复盘](testing.md) 匹配自然/付费、观看/进房/成交及统计窗口；缺数据留未知，不能把全场成交归给某一段。反馈更新本次使用判断与代表段理由，保留旧版，不把一次表现永久定义为“好/坏素材”。
